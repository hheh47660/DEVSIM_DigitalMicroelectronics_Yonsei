3. [1단계] 파이썬 객체지향으로 간이 시뮬레이터

이 단계의 물리 공식 세 줄이 전부입니다 (교과서 square-law 모델):

차단 · 선형 · 포화
Vg ≤ Vth :  Id = 0
Vd < Vg−Vth :  Id = k[(Vg−Vth)Vd − Vd²/2]
Vd ≥ Vg−Vth :  Id = (k/2)(Vg−Vth)²

k = µn·Cox·W/L 을 하나로 뭉친 이득 계수 — transistor width W = 1 µm 기준이라 전류 단위가 A/µm이 되고, 2단계 DEVSIM 결과와 같은 단위로 비교할 수 있습니다. 코드의 current() 메서드가 이 세 줄 그대로입니다.

이 단계에서 익히는 파이썬 도구

numpy — 숫자 배열을 반복문 없이 한 번에 계산
pandas — 결과를 표(DataFrame)로 정리, CSV 저장
plotly — DataFrame이면 그래프가 한 줄
클래스 — 아래 설명

클래스와 메서드란?

클래스(class)는 붕어빵 틀이고, 틀로 찍어낸 붕어빵 하나하나가 인스턴스입니다. 틀 안에는 각 붕어빵이 기억하는 값(속성 — 예: 문턱 전압)과, 그 값으로 일하는 함수(메서드 — 예: 전류 계산)가 들어 있습니다. 메서드 첫 인자 self는 "지금 이 붕어빵 자신"이라는 뜻입니다.

class SimpleMosfet:                 # 클래스: 소자 하나를 다루는 설계도
    def __init__(self, vth, k):     # 생성자: 인스턴스가 만들어질 때 자동 실행
        self.vth = vth              # 속성: 이 인스턴스가 기억하는 값

    def current(self, vg, vd):      # 메서드: 클래스 안의 함수
        ...                         # self로 자기 속성(self.vth 등)에 접근

mosfet = SimpleMosfet(0.6, 2e-4)    # 인스턴스 생성 (틀 → 붕어빵)
mosfet.current(1.0, 2.0)            # 메서드 호출

4. [2단계] DEVSIM으로 진짜 TCAD 시뮬레이터

1단계 공식 모델을 버리고, 반도체 물리 방정식을 실제로 푸는 엔진(DEVSIM)을 연결합니다. 푸는 방정식은 넷입니다 — 자세한 유도는 수업에서 다룹니다.

Poisson 방정식
∇·(ε∇ψ) = −q(p − n + ND − NA)

전하 분포로부터 전위 ψ와 전기장을 계산합니다. 게이트 전압이 바뀌면 채널 표면 전위와 캐리어 농도가 달라집니다.

전자 연속방정식
∇·Jn = q(R − G)

전자 전류가 소자 내부에서 보존되도록 합니다. 전자 drift와 diffusion이 함께 포함됩니다.

정공 연속방정식
∇·Jp = −q(R − G)

정공 전류 보존을 계산합니다. nMOS에서는 전자 전류가 주성분이지만 body와 접합 해석에 필요합니다.

Quasi-static C–V  [과제]
Cgg = dQg / dVg

각 게이트 전압에서 얻은 게이트 전하를 미분합니다. 예제에는 없습니다 — 여러분이 구현할 부분입니다.

config.yaml의 파라미터는 소자 어디에 있나

config.yaml에서 이 값들을 바꾸면 소자가 바뀝니다.

실행 순서

STEP2_RUN.batmosfet.py가 Id–Vg를 계산해 idvg.csv를 만듭니다 (수십 초). 1단계와 달리 곡선에 문턱 이하 전류(fA~nA)가 살아 있는 것을 확인하세요 — 공식 모델에는 없던 물리입니다.

5. [2단계] 코드가 도는 원리

위에서 아래로 호출이 내려가고, 아래에서 위로 결과가 올라옵니다.

한 번의 해석이 흘러가는 순서

왜 갈라질까? 전류(Id)는 전자가 실제로 흘러야 나오는 값이라 전자·정공 계산이 필요합니다. 반면 커패시턴스(C–V)는 각 전압에서 게이트에 쌓인 전하량만 알면 되므로 더 가볍게 구할 수 있습니다. — C–V 과제를 구현할 때 enable_transport()를 부르면 안 되는 이유입니다.

물리 수식은 어떻게 컴퓨터로 들어가나

신기하게도 방정식은 우리 코드 어디에도 없습니다. simulator.py가 CreateSiliconDriftDiffusion(...) 한 줄을 부르면 아래 4단계가 일어납니다.

위 문자열 수식이 실제로 적혀 있는 파일: .conda\Lib\site-packages\devsim\python_packages\simple_physics.py. 궁금하면 열어 봐도 됩니다 (과제 아님).

자주 나오는 용어 (이것만 알면 읽힌다)

용어뜻
TCADTechnology Computer-Aided Design의 약자. 반도체 공정·소자를 물리 방정식으로 시뮬레이션하는 분야를 통칭한다.
메시(mesh)소자를 계산하기 위해 잘게 나눈 격자. 격자 점마다 방정식을 세운다.
접점(contact)소자에 전압을 걸어 주는 금속 단자 (gate, source, drain, body 4개).
평형 상태아무 전압도 걸지 않은 상태. 모든 계산은 여기서 출발한다.
스윕(sweep)전압을 조금씩 바꿔 가며 같은 계산을 반복하는 것. 그 결과가 곡선이 된다.
Newton 반복답을 추측 → 오차 확인 → 수정을 반복해 정답에 다가가는 방법. 콘솔의 RelError가 그 오차.
solve"현재 조건에서 방정식을 풀어라"라는 DEVSIM 명령. 전압을 바꿀 때마다 다시 부른다.

6. [3단계] Streamlit으로 GUI 툴 만들기

시뮬레이터가 있어도 코드로만 돌리면 툴이 아닙니다. 마지막 단계에서는 Streamlit으로 브라우저에서 도는 GUI로 포장합니다.

Streamlit이 대신 해 주는 것

Streamlit은 파이썬 스크립트를 웹페이지로 바꿔 주는 라이브러리입니다. 웹 지식이 없어도 GUI가 만들어지는 이유입니다.

설명
실행bat을 더블클릭하면 Streamlit이 내 PC에 작은 웹서버를 켜고, 브라우저에 화면을 띄웁니다. 검은 콘솔 창이 그 서버입니다 — 닫으면 GUI도 꺼집니다.
화면 부품파이썬 한 줄이 화면 요소 하나입니다: st.slider() = 슬라이더, st.button() = 버튼, st.plotly_chart() = 그래프. HTML/CSS를 쓸 필요가 없습니다.
배치위치를 정해 줄 필요도 없습니다 — 코드에서 부른 순서대로 위에서 아래로 자동 배치됩니다. 좌우로 나누고 싶을 때만 st.columns()를 씁니다 (mini_app의 Device 1/2가 그 예).
갱신슬라이더나 버튼을 조작하면 스크립트 전체가 처음부터 다시 실행되면서 화면이 새로 그려집니다. mini_app을 조작하면서 코드와 화면을 같이 보면 이해됩니다.

실행 순서

DEMO.bat과 비교데모는 같은 구조에 2단계 TCAD 엔진을 연결하고 Id–Vd·C–V까지 얹은 완성본입니다. mini_app과 데모 사이의 거리가 곧 여러분의 최종 과제입니다.
